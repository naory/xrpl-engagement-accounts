# Hotel Stay Escrow (hotel@2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the hotel stay — booking, confirmation, check-in with a security deposit, entry disputes, deposit claims, silence defaults, default and backup rulings — end to end through the policy co-signer, on Testnet and in the web demo.

**Architecture:** A new template (`settlement-vault/hotel@2`) and policy layer (`pol_hotel@2.0.0`) express every outcome; the deal's state is never stored — policy *definitions* derive it from verified attestations, the ledger snapshot and the snapshot's close time. The co-signer gains an attestation store with signed receipts (deadline-checked at ingest), a pre-signed-default store, and `tick()`, which completes any due default through the normal `decide()` path. A shared `HotelFlow` driver runs the paths on Testnet for both the demo script and the web demo's live mode; the web demo's simulated mode replays a transcript generated by the real co-signer.

**Tech Stack:** TypeScript (Node ≥ 22.12, `tsx`), vitest, xrpl.js 4 (Batch / XLS-56, Tickets, Credentials), `@marcbachmann/cel-js` via `@eng/policy`.

**Spec:** `docs/superpowers/specs/2026-11-12-hotel-stay-escrow-design.md` (read it first; this plan argues from it). Background: `docs/use-cases/hotel-booking.md`.

## Global Constraints

- `templates/hotel@1.json` and `policies/hotel@1.1.0.json` are not modified. All new behaviour lives in `hotel@2` / `pol_hotel@2.0.0`.
- Weights: principal 3, counterparty 3, arbiter 4, backupArbiter 2, cosigner 2. Quorum 7.
- Service fee 50 bps on everything the hotel receives: `toFee == bps(toMerchant + toFee, 50)`. Refunds carry no fee.
- Only the guest (principal) opens disputes. A dispute counts only when BOTH a principal-issued `ENG/DISPUTE` Credential on the engagement account AND a receipted `party.dispute/1` from the principal exist.
- "Posted" = receipted by the co-signer; a statement arriving after its window is rejected at ingest and never stored.
- Hotel claims are capped at the deposit.
- Every check the web demo displays comes from a co-signer decision record (rule id, result, reason) — never a hard-coded string.
- Test keys come from `packages/policy/test/fixtures.ts` `wallet(name)` (deterministic, TEST ONLY). Testnet keys are generated fresh per run.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work happens on branch `feat/hotel-stay-escrow`.
- After every task: `npm run typecheck` clean and `npm test` green.

## Review Focus

1. **Closing default on an account < 256 ledgers old** — `AccountDelete` fails `tecTOO_SOON`, and a failed `ALLORNOTHING` Batch burns its outer Ticket (F2). Expect: the co-signer refuses (B11 `WOULD_FAIL`). Test in Task 1.
2. **A statement posted after its window** (claim after `claimBy`, check-in after `checkInBy`, entry dispute after `entryDisputeBy`). Expect: ingest throws `LATE`, nothing stored, no receipt. Test in Task 5.
3. **Dispute Credential with no receipted dispute attestation** (or stray RLUSD from a non-party). Expect: the credential alone doesn't count as a dispute; a balance change still refuses the default (`BALANCE_CHANGED`). Test in Task 3.
4. **`tick()` called twice, or after the account is gone.** Expect: the second call doesn't return a second completion for a default already in flight; a closed account yields nothing. Test in Task 6.
5. **A pre-signed blob with the wrong signers, a bad signature, or the wrong blueprint.** Expect: `storePresigned` throws and stores nothing. Test in Task 6.

### Task 6: Pre-signed defaults and `tick()`

**Files:** Modify `packages/cosigner/src/service.ts`, `packages/cosigner/src/server.ts`; Test `packages/cosigner/test/hotel-service.test.ts`.

**Interfaces:**
- Produces:
  - `CosignerService.storePresigned(engagementId: string, outcome: string, blob: string): void`
  - `CosignerService.tick(engagementId: string): Promise<TickResult[]>`, `interface TickResult { outcome: string; stage: string; decision: 'SIGN' | 'REFUSE'; failing: string[]; record: Statement; blob?: string }` — `blob` is the fully signed, submittable blob (stored signatures + the co-signer's), present only on SIGN.
  - HTTP `POST /v1/engagements/:id/presigned` `{ outcome, blob }` → `{ ok: true }`; `POST /v1/engagements/:id/tick` → `TickResult[]`.
- `storePresigned` checks: the outcome is `presigned` in the template; the blob's `Signers` are exactly the outcome's signer set minus `finalSigner` (resolved via `record.parties`), each signature verifies (`encodeForMultisigning` + `ripple-keypairs` `verify`, as in `service.test.ts`); the tx uses Tickets (outer `TicketSequence`, no `LastLedgerSequence`) and `matchesBlueprint(outcome.blueprint)`. Otherwise throw and store nothing.
- `tick` runs `decide({ stage: outcome.policyStage, txBlob })` for each stored default (serialised by the existing per-engagement lock). On SIGN it returns `combine([stored, signerBlob])`. A default with a SIGN already in flight (existing in-flight set, same `proposedTxHash`) returns its existing blob instead of re-signing. An engagement whose account no longer exists returns `[]`.
