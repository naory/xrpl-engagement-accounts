# Per-deal costs

XRP an engagement account locks as reserve, and XRP it burns as fees, for one deal. The marked block is regenerated from `npm run validate-templates` and from `hotelTickets` (`packages/cosigner/src/hotel/flow.ts:87`).

## Tickets and reserve

`validate-templates` runs `validateTemplate` on each file in `templates/` and prints `ticketsNeeded` and the reserve (`validateTemplate` (`packages/core/src/cli.ts:28`), `ticketsNeeded` (`packages/core/src/cli.ts:31`)). The reserve is the base plus one increment for each trust line, the signer list, and each Ticket (`reserve` (`packages/core/src/template.ts:246`)).

Those figures use the validator defaults: a base of 1 XRP (`reserveBaseDrops` of 1000000 drops) and an owner increment of 0.2 XRP (`reserveIncDrops` of 200000 drops) (`reserveBaseDrops` (`packages/core/src/template.ts:243`), `reserveIncDrops` (`packages/core/src/template.ts:244`)). Those match Testnet and Mainnet today. Reserves are network-set and may change. A live snapshot reads the ledger fee object's `BaseFeeDrops` and `ReserveIncrementDrops`, with the same 10-drop and 200000-drop fallbacks (`baseFeeDrops` (`packages/cosigner/src/snapshot.ts:75`), `reserveIncDrops` (`packages/cosigner/src/snapshot.ts:76`)).

Stay rows for `settlement-vault/hotel@2` are 1 through 14 nights. The Ticket count is `hotelTickets` (`packages/cosigner/src/hotel/flow.ts:87`). The reserve is `validateTemplate` on a copy whose `default.chargebackStay` `variants.max` is the number of stay variants that call booked (`variants` (`templates/hotel@2.json:23`), `tickets` (`packages/core/src/template.ts:239`)).

The cap is 14 nights. The template sets `variants.max` to 13 (`variants` (`templates/hotel@2.json:23`)). `hotelTickets` reads that into `STAY_VARIANT_MAX` and adds a `default.chargebackStay` variant only while `nights - 1` is within it, so 14 nights books every variant (`hotelTickets` (`packages/cosigner/src/hotel/flow.ts:75-92`)). The policy states the same cap as `maxStayVariantNights` 14 (`maxStayVariantNights` (`policies/hotel@2.0.0.json:38`)).

Past 14 nights, `hotelTickets` falls back to the 1-night Ticket set: the six fixed pre-signed outcomes, and no mid-stay chargeback variants (`STAY_VARIANT_MAX` (`packages/cosigner/src/hotel/flow.ts:92`)).

Registration does not currently refuse a stay of 15 nights or more. `registerLocked` rejects the terms only when `stayTermsFindings` returns a problem (`stayTermsFindings` (`packages/cosigner/src/service.ts:303`)). From its definition through its final return, that function checks pinned terms, that `terms.nights` matches the mandate dates, that `terms.nightly` is floor(amount ÷ nights), and that the ruling window sits inside the policy bounds (`stayTermsFindings` (`packages/cosigner/src/service.ts:1100-1135`)). It does not read `maxStayVariantNights`. Such a deal registers, and open books it with `hotelTickets`, which is the 1-night Ticket set and no `default.chargebackStay` variants (`hotelTickets` (`packages/cosigner/src/hotel/flow.ts:241`)).

This is a known gap. Refusing those stays would be a co-signer change, and no new hotel features are merged (`Hotel` (`docs/SCOPE.md:11`)). This sheet does not make that change.

## Open and close fees

`batchFee` charges one reserve increment per inner `AccountDelete`, plus the base fee times `(2 + the other inner transactions + signatures) × headroom` (`batchFee` (`packages/ledger/src/xrpl-io.ts:43`)). `buildOpenBatch` asks for one signature and headroom 2 (`buildOpenBatch` (`packages/ledger/src/xrpl-io.ts:54`)). It adds a `TicketCreate` inner only when `ticketCount` is greater than zero (`ticketCount` (`packages/ledger/src/xrpl-io.ts:61`)).

A pre-signed hotel close passes `signatures` 3 and leaves headroom at the default (`signatures` (`packages/cosigner/src/hotel/flow.ts:648`), `headroom` (`packages/ledger/src/xrpl-io.ts:46`)). An agreed live close uses 3 signatures (`liveClose` (`packages/cosigner/src/hotel/flow.ts:425`)). A ruling close uses 2 (`liveClose` (`packages/cosigner/src/hotel/flow.ts:438`)). The procurement owner's close uses 1 (`signatures` (`packages/cosigner/demo/b1-testnet.ts:284`)).

Generated fee figures use the 10-drop fallback written in `baseFeeDrops`, the value used when the ledger fee object has neither `BaseFeeDrops` nor `BaseFee` (`baseFeeDrops` (`packages/cosigner/src/snapshot.ts:75`)), and the validator default reserve increment (`reserveIncDrops` (`packages/core/src/template.ts:244`)). The AccountDelete special fee shown there is that increment once per delete (`deletes` (`packages/ledger/src/xrpl-io.ts:44`)).

## Where the reserve goes at close

`buildReclaimDeletePlain` builds an `AccountDelete` whose destination is `deleteTo`, and the comment says leftover XRP, including the reserves, returns to the operating account (`buildReclaimDeletePlain` (`packages/cosigner/src/precreate.ts:35`)). The pool passes the operating account as `deleteTo` (`buildReclaimDeletePlain` (`packages/cosigner/src/pool.ts:166`)). The hotel engagement record sets `deleteTo` to the service account (`deleteTo` (`packages/cosigner/src/hotel/flow.ts:302`)). `buildCloseBatch` writes that destination onto the inner `AccountDelete` (`AccountDelete` (`packages/ledger/src/xrpl-io.ts:78`)).

## Ledger age before AccountDelete

`ACCOUNT_DELETE_MIN_AGE` is the number of ledgers AccountDelete waits: the account's Sequence plus that constant must be at or before the current ledger index (`ACCOUNT_DELETE_MIN_AGE` (`packages/policy/src/facts.ts:12`)). The hotel flow waits on a constant of the same name (`ACCOUNT_DELETE_MIN_AGE` (`packages/cosigner/src/hotel/flow.ts:107`)). `wouldSucceed` refuses a closing pre-signed outcome before that age (`wouldSucceed` (`packages/policy/src/facts.ts:152`)). The pool keeps an account `aging` until `agingLedgers` have elapsed since creation (`agingLedgers` (`packages/cosigner/src/pool.ts:141`)). The pool CLI sets `agingLedgers` to the same count (`agingLedgers` (`packages/cosigner/src/pool-cli.ts:89`)).

## Pre-create funding

`validate-templates` passes `preCreateFundingDrops` into the validator (`preCreateFundingDrops` (`packages/core/src/cli.ts:28`)). V9 compares the reserve plus `feeHeadroomDrops` with that funding (`feeHeadroomDrops` (`packages/core/src/template.ts:248`)). The generated block records both amounts.

`precreateDrops` funds the base reserve, one increment for the trust line and the signer list, one increment per Ticket from `hotelTickets`, and a flat drops literal on that same line (`precreateDrops` (`packages/cosigner/src/hotel/flow.ts:177`)). The pool CLI's unset `ENG_CREATE_DROPS` falls back to the `createAmountDrops` literal (`createAmountDrops` (`packages/cosigner/src/pool-cli.ts:88`)). The procurement demo pays the new account `xrpToDrops` of a whole-XRP literal (`xrpToDrops` (`packages/cosigner/demo/b1-testnet.ts:112`)).
